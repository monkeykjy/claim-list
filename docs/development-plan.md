# ClaimList 开发工作计划

范围更新：下列第一至第六阶段是原匿名版本的实施记录。新增 [ACC-001](account-system.md) 已在第七阶段完成，具有独立账号验收记录。

本计划依据产品需求、页面与状态说明、AUTH-001 和研发交接制定。阶段按依赖顺序推进，每阶段同步更新实现状态和 README；计划中的功能不代表已经实现。

## 第一阶段：工程基础（已完成）

- 初始化 Next.js App Router、TypeScript 严格模式、Tailwind CSS。
- 使用 pnpm 管理依赖，固定版本并提交锁文件；使用 Node.js 22 LTS。
- 配置 ESLint、Prettier、类型检查和生产构建命令。
- 建立中文页面布局和明确标注实施进度的起始页。
- 忽略运行数据、环境配置和构建产物，保留现有 MIT 许可证和需求文档。
- 验收：依赖可安装，代码检查、类型检查、格式检查和生产构建通过；启动后检查页面与移动端布局，保存截图。

## 第二阶段：SQLite 与业务数据基础（已完成）

- 选择并记录 SQLite 访问库，实现仅供服务端使用的数据库模块。
- 建立站点配置、条目和管理员会话所需结构；采用版本化迁移，默认数据库放在持久化 `data/` 目录。
- 标题规范化仅去首尾空白，保留大小写、内部空格和标点差异；数据库唯一约束作为最终保障。
- 批量新增采用事务；认领采用条件更新，确保只能从未认领状态成功写入一次。
- 明确输入长度、批量数量上限及错误返回格式；使用数据库约束保障认领与完成信息一致。
- 验收：重复标题拒绝、整批回滚、并发新增及并发认领通过真实 SQLite 集成测试；迁移可作用于已有数据库。

## 第三阶段：初始化与管理员认证（已完成）

- 确定一次性初始化口令的生成、交付和失效方案；完成首次设置及并发初始化保护。
- 密码仅存安全哈希；使用 HttpOnly Cookie 建立 24 小时服务端可失效的会话。
- 所有管理操作统一执行服务端授权，落实请求来源校验及登录尝试限制。
- 实现登录、退出、修改密码和真正可用的 `pnpm reset:passwd`；隐藏输入新密码，修改或重置使所有旧会话失效。
- 验收：初始化后不能重开；无会话请求被拒绝；到期、退出、改密和重置按规则失效；重置失败保留旧凭据，成功保留业务数据。

## 第四阶段：管理员条目维护（已完成）

- 批量新增：兼容常见换行，跳过空行，标注冲突标题和原始行号，失败保留全文。
- 实现修改标题、删除确认、更正显示姓名、释放认领、代为完成、重新打开。
- 实现清单名称、说明和三个列名的配置，状态值保持固定。
- 验收：改标题保留身份与状态；改名不转移身份；释放清空归属及完成信息；重新打开保留归属；删除后同名新条目不继承历史。

## 第五阶段：公开清单与参与者流程（已完成）

- 实现空状态、按录入顺序展示列表、填写姓名认领、标记完成。
- 浏览器生成随机 UUID 并复用；存储不可用时提示。服务端可靠获取客户端 IP，仅信任明确配置的受控代理。
- 完成授权严格保留“IP 匹配 OR UUID 匹配”，公开接口不返回身份凭据；保留 AUTH-001。
- 页面可见时每 30 秒刷新，重新获得焦点及操作成功后更新；服务端数据与本地草稿独立管理。
- 覆盖冲突、条目删除、会话过期、刷新失败、提交结果不确定；保护刷新及失败后的非敏感输入，不持久保存密码或初始化口令。
- 验收：同 UUID 不同 IP 允许、同 IP 不同 UUID 允许、均不同拒绝；未认领不能完成；重复完成保留首次时间；刷新和失败不丢草稿。

## 工程约定与范围

- `src/app/` 放页面、布局及后续 HTTP 入口；共享 UI 按需要提取到 `src/components/`。
- 后续数据库、认证和业务规则放在 `src/server/`，使用 `server-only` 边界；浏览器身份与草稿逻辑独立放置，避免导入服务端模块。
- 数据库测试使用临时数据库；需要业务测试时再配置测试框架，不设置空跑测试或虚假密码重置命令。
- 技术细节由各阶段选定并记录；新增鉴权防护属于实施措施，不改变匿名使用能力；匿名条目保留 OR，账号条目按 ACC-001 授权。
- 可选参与者账号已纳入新增范围；多清单、多人认领、自定义状态、看板、评论、通知和审批仍不增加。
