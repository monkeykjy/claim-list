# ACC-001 账号系统开发计划

日期：2026-09-29。状态：7.1–7.6 已实施并通过验收；验证入口及范围见 [验收记录](verification.md)。

依据：[可选账号与匿名任务归属](account-system.md)、产品需求、页面与状态、AUTH-001，以及现有匿名版实现。本文件细化总计划的第七阶段；已确认产品规则以 ACC-001 为准，以下技术默认值已在实施中落地。

## 1. 目标与边界

- 支持邮箱、密码、确认密码、姓名四字段注册；登录使用邮箱和密码，注册成功即登录。
- 继续允许匿名认领。已登录认领由服务端读取账号姓名与 ID，不允许客户端指定实际归属。
- 注册登录或已有账号登录成功时，自动绑定当前 UUID 下已认领且尚无账号归属的条目，包含进行中和已完成条目。
- 未绑定条目保留 IP OR UUID 完成规则；已绑定条目只允许归属账号的有效会话完成，不回退到 IP 或 UUID。
- 管理员可以重置指定参与者密码；参与者和管理员会话、权限、退出及密码重置相互独立。
- 不增加邮箱验证、邮件找回、第三方登录、账号资料编辑、账号删除、复杂角色或独立“我的任务”页面。

保留当前已交付交互：完成条目沉底，两组内按录入顺序；不常驻显示身份不匹配文案；认领冲突在条目内显示红底红叉及当前认领人，清除该条目草稿并刷新；成功显示绿底绿勾。提示 5 秒后消失。普通刷新及失败保护输入。

## 3. 已采用的技术默认值

密码最低 8 位、不要求字符组合已由用户确认；其余默认值是研发选择，不将其表述为用户已经单独确认的产品约束。

| 项目       | 采用方案                                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 邮箱       | 去首尾空白并统一小写，最长 254 字符，使用一致的服务端格式校验；规范化值建唯一约束。不删除 `+` 后缀、不合并点号或不同域名                   |
| 姓名       | 沿用 1–60 字符、去首尾空白、允许重名；认领时复制账号姓名作为当时的展示值                                                                   |
| 密码       | 已确认最低 8 位，不要求字符组合；保留 128 字符上限及随机盐 scrypt；管理员和参与者的设置、注册、修改与重置统一校验，确认密码不存储          |
| 参与者会话 | 采用 30 天固定有效期，不做滑动续期；每次登录发新令牌，多设备可各自登录。普通退出只撤销当前参与者会话；密码重置撤销该账号全部会话           |
| 管理员会话 | 保留 24 小时，现有 Cookie 与命令含义不变                                                                                                   |
| 会话存储   | 独立 `participant_sessions` 表和 `claimlist-participant` HttpOnly Cookie；只存令牌摘要，SameSite=Strict，HTTPS 使用 Secure                 |
| 登录提示   | 首页轻量非阻断，仅登录和注册入口；无需点击跳过按钮即可匿名使用；退出账号需弹窗确认                                                         |
| 请求与限流 | 沿用同源校验；注册、参与者登录、管理员登录使用独立计数命名空间。参与者登录同时按 IP 和规范化账号摘要限制尝试，初始阈值为每项 15 分钟 10 次 |
| 资料与恢复 | 本轮无个人资料编辑；管理员确认目标账号后输入两次新密码，通过现有私下渠道交付，不实现邮件服务或新增找回入口                                 |

## 4. 实施顺序与任务

阶段顺序：**7.1 数据迁移 → 7.2 认证与绑定 → 7.3 条目权限 → 7.4 参与者界面 → 7.5 管理员密码恢复 → 7.6 完整验收与交付**。

### 7.1 数据结构与升级基础

- [x] 在现有迁移之后追加 `user_version=2`，不重写已交付 v1 迁移。
- [x] 建立 `participant_accounts`：稳定 ID、规范化唯一邮箱、姓名、密码哈希、创建/更新时间。
- [x] 建立 `participant_sessions`：令牌摘要、账号外键、过期时间及必要索引。
- [x] 条目新增可空 `owner_account_id` 外键；数据库约束保证未认领条目不能残留账号归属。索引支持当前 UUID 下未绑定条目的查询。
- [x] 升级后旧条目归属全部为空，逐项保留 ID、录入顺序、标题、显示姓名、IP、UUID、认领/完成及创建/更新时间，管理密码和原管理会话也保留。
- [x] 提前打通维护工具的版本兼容：识别 v1/v2，拒绝未知新版本；旧备份在暂存库中迁移后恢复。

验收：用真实 v1 结构和样本数据升级，而不是先由最新 Store 创建空库；验证全字段保留、重复迁移幂等、迁移异常整次回滚、全新安装依次建立 v1/v2、外键与唯一约束生效。

### 7.2 参与者认证与原子绑定

- [x] 实现注册、登录、当前会话查询和退出；可采用 `/api/participant` 作为独立入口，避免与现有管理员 `login/logout` 动作混淆。
- [x] 抽出可复用的密码哈希/比较代码，不复用管理员会话或权限。
- [x] 注册校验邮箱、姓名和两次密码；数据库唯一约束处理并发注册同一邮箱。
- [x] 将账号创建（注册时）、会话写入、UUID 自动绑定放在同一个写事务中，事务成功后才设置 Cookie 和返回绑定数量。
- [x] 绑定严格限定 `claimant IS NOT NULL AND claim_uuid = 当前UUID AND owner_account_id IS NULL`，使用条件更新结果计算真实数量。
- [x] 只更新账号归属及并发用的 `revision`；不重写条目显示姓名或历史时间，完成状态与排序保持不变。
- [x] 绑定失败整次回滚，不产生“登录成功但绑定失败”的半完成状态。重复登录可返回本次新增绑定数 0，不覆盖任何已有归属。
- [x] 缺少合法浏览器 UUID 时明确报错并保持登录/绑定原子性；浏览器存储不可用仍可用本次访问的随机 UUID，但不承诺找回旧 UUID 下条目。
- [x] 将限流计数分域，避免参与者登录耗尽管理员额度；保持密码、令牌和邮箱信息不进入公开清单或日志。

验收：重复邮箱、允许同名、错误密码、会话到期/退出、多设备会话、零条绑定、已完成条目绑定、同 IP 不同 UUID 不绑定、切换账号不转移、重复登录幂等、绑定失败回滚及并发登录争抢同一匿名条目。

### 7.3 认领、完成及管理员纠错权限

- [x] 服务端在写事务中读取最新参与者会话及条目归属，再决定姓名、归属和操作权限。
- [x] 已登录认领取服务端账号 ID/姓名，忽略客户端伪造的姓名或归属；匿名认领继续使用姓名输入并记录 UUID/IP。
- [x] 请求明确提交预期认领模式。客户端认为已登录但会话已过期时返回账号登录失效，不能静默转成匿名认领；用户重新登录或明确选择匿名后才能重试。账号切换导致提交身份与页面不一致时要求刷新确认。
- [x] 统一权限判断供 `canComplete` 和提交使用，避免按钮状态与写入授权采用不同规则。
- [x] 已绑定：仅归属账号有效会话可以完成。未绑定：继续 IP OR UUID，包括已登录用户操作尚未绑定条目的情况。
- [x] 管理员更名保留账号归属；释放清空归属和全部认领/完成信息；重新打开保留归属；代为完成保留原独立管理授权。
- [x] 绑定提高条目 revision，使旧管理编辑不能静默覆盖新归属相关状态；重复完成保持首次完成时间。

必须验证的权限矩阵：

| 条目           | 操作者                              | 预期                    |
| -------------- | ----------------------------------- | ----------------------- |
| 未绑定、已认领 | UUID 匹配，IP 不同                  | 允许完成                |
| 未绑定、已认领 | IP 匹配，UUID 不同                  | 允许完成，保留 AUTH-001 |
| 未绑定、已认领 | IP 与 UUID 都不同                   | 拒绝                    |
| 已绑定账号 A   | A 有效会话，其他设备/IP/UUID        | 允许                    |
| 已绑定账号 A   | 无会话或账号 B，即使原 IP/UUID 匹配 | 拒绝                    |
| 未认领         | 参与者或管理员                      | 拒绝直接完成            |
| 任意已认领     | 有效管理员授权执行代为完成          | 允许                    |

并发验收：分别调度“先绑定后完成”和“先完成后绑定”。前者必须执行账号授权；后者允许在绑定前按匿名规则完成，随后绑定仍保留其完成时间。同一账号或不同账号同时绑定、管理员释放与绑定、认领与绑定都只能产生满足规则的最终状态。

### 7.4 参与者界面与会话同步

- [x] 首页增加“正在匿名使用。登录后可跨设备管理已认领的任务。”轻提示，以及登录、注册入口；无“暂不登录”按钮，可直接匿名使用，刷新不阻断。
- [x] 注册四字段、登录两字段，可在轻量表单面板切换；登录后展示当前姓名及退出入口，管理员入口始终独立。
- [x] 登录后待认领条目显示账号姓名与认领按钮，无需再次输入姓名；退出后恢复匿名输入。
- [x] 登录成功显示实际绑定数量，零条时只提示登录成功；成功反馈与已有绿勾样式一致，错误反馈使用红叉。
- [x] 列表刷新同时同步当前会话、条目归属提示和 `canComplete`；定时刷新、焦点刷新以及登录/退出/绑定成功后立即更新，避免过期请求覆盖新状态。
- [x] 账号条目未登录时提供登录引导；其他账号不显示完成按钮。沿用当前列表不常驻展示身份不匹配段落的交互约定，具体拒绝原因在尝试操作或身份变化时提示。
- [x] 邮箱、姓名等非敏感输入可保留；密码和确认密码不写 localStorage/sessionStorage。切换登录态不清掉无关条目的未提交输入。
- [x] 管理员重置密码或其他标签页切换身份后，本页刷新立即更新状态；旧页面提交不得绕过服务端校验。

验收：多浏览器上下文分别模拟匿名、账号 A、账号 B 和管理员；覆盖跨设备、跳过登录、存储失效、请求丢失、会话过期、草稿保护与手机布局。保留完成沉底、红叉/绿勾行内提示及认领冲突简化行为。

### 7.5 管理员重置参与者密码

- [x] 管理页增加参与者查询和账号选择，展示足以区分同名账号的邮箱/姓名；只通过已验证的管理员接口返回这些信息。
- [x] 重置前明确目标账号，输入新密码和确认密码并确认操作；不显示旧密码，不修改姓名或任务归属。
- [x] 事务内检查管理会话，更新指定账号密码哈希并撤销该账号全部参与者会话；其他参与者和管理员会话不受影响。
- [x] 重置相应参与者登录限制时按账号命名空间处理；管理员 `pnpm reset:passwd` 只处理管理员凭据/会话及其限流记录。
- [x] 未登录、普通参与者 Cookie、伪造账号 ID 或过期管理会话都不能执行重置。
