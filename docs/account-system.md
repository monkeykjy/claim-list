# ACC-001：可选账号与匿名任务归属

确认日期：2026-09-29。状态：已实现并通过账号专项验收，证据见 [验收记录](verification.md)。

## 1. 目的与范围

允许参与者通过账号跨设备管理自己的任务，同时保留匿名使用。单清单、内网部署、管理员独立管理密码及现有条目状态保持不变。

未登录访问时提示“正在匿名使用。登录后可跨设备管理已认领的任务。”，仅提供登录、注册入口，不显示“暂不登录”按钮；未登录可直接匿名使用，不因刷新弹出阻断提示；保留可随时进入的登录入口。

## 2. 注册、登录与姓名

| 注册字段 | 规则                                                   |
| -------- | ------------------------------------------------------ |
| 邮箱     | 完整邮箱地址作为登录账号，必须唯一；不再设置独立用户名 |
| 密码     | 至少 8 位，不要求字符组合；服务端保存安全哈希          |
| 确认密码 | 必须与密码相同，仅用于校验，不持久保存                 |
| 姓名     | 必填，作为登录后认领时的显示姓名；允许不同账号同名     |

登录只输入邮箱和密码。第一版不做邮箱验证、邮件找回、第三方登录或复杂角色体系。邮箱只是登录标识，不证明邮箱所有权或员工身份；不因填写某个邮箱获得管理权限。

匿名认领继续手动填写姓名。已登录认领直接使用账号姓名，点击确认即可，无需再次填写；服务端根据有效会话读取账号 ID 和姓名，不信任客户端自行指定归属。新认领仍记录 UUID、IP 和认领时间。

条目归属使用稳定账号 ID，姓名只是展示信息。旧条目绑定账号时保留原有显示姓名。暂不扩展个人资料编辑或批量改名功能。

## 3. 登录后的自动绑定

注册并登录成功、或已有账号登录成功时，将满足以下全部条件的条目绑定到当前账号：

- 条目已经被认领；
- 认领 UUID 与当前浏览器 UUID 相同；
- 条目尚未绑定任何账号。

进行中和已完成条目都包含在内。保留条目 ID、标题、原显示姓名、认领 IP、UUID、认领时间、状态和完成时间。此处“转移”是建立账号归属，不是复制条目或重新认领。

只依据当前 UUID 自动绑定，绝不按 IP 或姓名迁移。已归属其他账号的条目不能被覆盖。重复登录保持幂等；同一浏览器换账号时，不会将已经绑定的条目转给新账号。

自动处理成功后显示实际绑定数量，例如“已将当前浏览器认领的 3 个任务关联到你的账号”。没有符合条件的条目时正常登录，不创建虚假迁移记录。绑定失败不得显示成功；重试不得覆盖其他账号或重复迁移。

示例：匿名认领 A、B 后登录甲账号，A、B 归甲。退出再登录乙账号，A、B 仍归甲。后来匿名认领的新条目 C 若尚未绑定，登录乙账号时可归乙。

## 4. 完成权限按条目归属区分

| 条目归属               | 参与者完成权限                                                           |
| ---------------------- | ------------------------------------------------------------------------ |
| 未绑定账号的已认领条目 | 当前 IP 或 UUID 与认领信息任一匹配；操作者是否登录不改变该匿名条目的规则 |
| 已绑定账号的条目       | 必须持有归属账号的有效登录会话；不允许通过 IP 或 UUID 回退放行           |
| 管理员纠错             | 通过独立管理授权，保留代为完成、释放认领和重新打开能力                   |

账号任务允许在其他设备登录对应账号后完成。退出账号后，即使仍为原 IP 或 UUID，也不能完成账号任务。服务器根据最新归属判断权限，不能信任页面旧状态。

未认领不能完成、重复完成保持幂等、参与者不能自行取消认领或撤销完成等规则继续有效。

“我的任务”如用于展示或归属标记，应依据账号 ID 或未绑定条目的当前 UUID，绝不按 IP 判断；这项定义不要求额外增加独立页面。

## 5. 管理与密码恢复

普通参与者账号与管理员认证相互独立，登录普通账号不获得管理权限。管理会话仍为 24 小时。参与者点击“退出账号”先弹窗确认，取消保持登录，确认后仅退出当前设备会话。

- 管理员可为指定参与者账号重置密码，使该账号已有登录会话失效，保留其任务归属。
- `pnpm reset:passwd` 继续只重置管理密码并失效管理会话，不重置参与者账号密码。
- 更正条目显示姓名不能改变账号 ID、认领 UUID 或 IP。
- 释放认领同时清除账号归属、显示姓名、UUID、IP、认领时间和完成时间。
- 重新打开保留账号归属及原认领信息，仅清除完成时间。
- 更换实际负责人仍采用释放后重新认领，不通过编辑姓名转移任务。

## 6. 研发落地要求

在现有数据库上执行版本化迁移，引入参与者账号、参与者会话和可空的条目账号归属。升级后所有旧条目保持原状态和原身份信息，账号归属为空；不能按相同姓名或 IP 合并归属。

自动绑定使用事务或等价的条件更新，确保只有尚无账号归属的条目可被绑定。绑定、认领和完成并发时必须以服务端最新身份与归属校验，避免账号已绑定后仍通过匿名权限写入。

参与者会话与管理会话分别授权和失效；密码、会话凭据、他人的邮箱和身份信息不加入公开清单响应。更新备份恢复、迁移和验收覆盖，使新增账号数据与任务归属一并保留。

已确认：所有管理员及参与者密码最低 8 位，不要求字符组合；设置、注册、修改及重置规则一致。实现保留现有 128 字符输入上限。

邮箱规范化方式、参与者会话有效期及登录提示关闭状态的保存方式，已按 [开发计划](account-development-plan.md#3-已采用的技术默认值) 落地。管理员原有 24 小时会话规则保持不变。

- [x] 登录只需邮箱与密码；登录后认领无需填写姓名，使用服务器读取的账号姓名和账号 ID。

- [x] 参与者密码重置只使该账号旧会话失效；普通账号无管理权限；管理密码重置保持独立。

## 8. 与原有需求的关系

本决定替代“完全不引入参与者账号”的范围限制。原 IP OR UUID 规则收窄为未绑定账号的条目；[AUTH-001](known-limitations.md#auth-001) 继续有效，不能删除或表述为已经彻底解决。其他条目管理、单清单和内网部署规则不变。
