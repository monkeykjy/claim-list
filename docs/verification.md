## 交付边界

依据用户澄清，本次交付不绑定某台服务器或固定域名。应用配置、systemd 和 Nginx 示例、迁移/备份/恢复流程已提供。实际部署者需在自己的系统上验证 Node 和原生依赖安装、系统服务权限、反向代理来源信息、域名证书、允许网段及范围外不可访问；这些现场条件不声称已验证。

上述历史验收基于单实例、内网、无需参与者账号及 IP OR UUID 规则。新增 ACC-001 保留匿名使用与匿名条目 OR，并为账号绑定条目引入独立账号校验，新增专项验证已完成，见下文。`AUTH-001` 仍为已接受局限；没有引入多清单或自定义工作流。没有生产数据、密码、初始化口令或 SQLite 运行文件纳入 Git。

- 后续启动配置调整：pnpm dev/start 明确监听 0.0.0.0:1234；自动直连来源覆盖本机实际 IP，仍校验同源并拒绝任意 Host。

- 列表排序调整：标记完成后移入底部已完成区域，重新打开后回到未完成区域；两组内保留录入顺序。现有数据库状态纠错测试及浏览器完成/重新打开流程增加顺序断言。

- 认领冲突简化：服务端返回当前认领人姓名；前端在对应条目的认领人下方显示 5 秒提示框并刷新列表，冲突草稿从页面和 sessionStorage 清除。浏览器验收检查行内提示位置、自动消失、最新认领人、草稿清除及重载行为，截图见 [认领冲突提示](screenshots/claim-conflict-tip.png)。网络结果不确定时仍保留输入。

专项断言见 `tests/accounts.test.ts`、`tests/fixtures/account-race.ts` 与 `e2e/flows.spec.ts`：

- 用独立 v1 SQL 样本验证逐字段升级、管理密码/会话保留、幂等及迁移失败整次回滚；升级前备份保持 v1。分别恢复 v1/v2，验证会话撤销、账号凭据与归属保留；拒绝未来版本和损坏/迁移失败输入，当前数据不被替换。
- 邮箱去首尾空白、大小写规范化、唯一约束、允许同名；8 位密码接受，7 位、不一致密码、空姓名、无效邮箱和缺失 UUID 拒绝。
- 进行中及已完成条目按 UUID 绑定，历史姓名和时间保留；同 IP 不同 UUID 不绑定、账号切换不转移、重复登录新增数量为零。注入绑定失败验证账号/会话/归属全部回滚。
- 多进程同时注册、同账号/不同账号登录争抢绑定；绑定与完成的两种事务顺序，绑定与释放/认领竞争，最终归属满足规则。
- 匿名 IP OR UUID 矩阵；账号条目跨设备允许、其他账号或无会话即使 IP/UUID 匹配仍拒绝。显示权限与提交授权共用规则，改名/重开不改变归属，释放清空归属。
- 多设备参与者会话、当前设备退出、30 天到期、管理员与参与者授权隔离；重置仅撤销目标账号全部会话，保留归属，其他账号和管理员不受影响；限流命名空间相互独立。
- 浏览器实际注册绑定两条任务、登录认领免填姓名、跨设备完成、账号切换、保留匿名草稿、可跳过登录；通过管理界面查询与重置后，旧页面认领被拒绝并刷新，旧密码失败、新密码成功。
- 跨标签页登录态同步、登录已提交但响应丢失时不虚报成功并刷新核对、localStorage/sessionStorage 均不可用时仍可登录与认领；密码不写浏览器存储。
- 原完成沉底、冲突红底红叉/成功绿勾及 5 秒消失、输入保护、可见轮询与焦点刷新全部回归通过。
