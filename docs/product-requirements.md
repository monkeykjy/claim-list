# ClaimList：第一版产品需求

新增决定：[ACC-001 可选账号系统](account-system.md) 已实现并通过专项验收；证据见 [验收记录](verification.md)。

状态：第一版需求基线，2026-09-29 更新。用户已接受需求收口建议，并确认以内网部署面向内部开发者使用。本仓库用于正式研发，原匿名版业务功能及通用部署交付已有实现记录，账号增量已完成专项实现和验收；实际进度与验证范围见 [研发交接](development-handoff.md)。明确标注为“建议”的实现细节可在研发时调整。

## 1. 产品定位

已确认：产品名称为 **ClaimList**。产品名称与用户配置的清单名称相互独立，清单名称及字段文案仍可按使用场景调整。

面向“有一批事情需要有人领取并完成，但不需要看板和完整项目管理”的场景，提供一个轻量共享清单。

核心流程：**管理员录入条目 → 参与者匿名填写姓名或登录后直接认领 → 按条目归属校验并标记完成**。

开发任务是首个使用场景。通用概念采用“条目、认领人、状态”；开发任务场景可以显示为“任务、开发者、完成情况”。

新增可选参与者账号，保留匿名使用；不引入多清单、看板、审批、评论、通知或自定义工作流。

### 使用与访问范围

第一版部署在内网，供内部开发者使用。任何能访问该内网站点的人均可查看条目及姓名、参与认领；应用不验证员工身份，提供可跳过的邮箱账号登录。访问范围由部署网络控制，不对公网开放。搜索引擎收录设置不能替代网络访问限制。

## 2. 用户与权限

| 角色                 | 能力                                                                         |
| -------------------- | ---------------------------------------------------------------------------- |
| 访客／参与者         | 查看清单，无需登录或密码；填写个人信息认领条目                               |
| 符合身份条件的参与者 | 将自己认领的条目标记为完成；身份条件见第 6 节                                |
| 管理员               | 设置管理密码；验证密码后维护条目、纠正认领和完成情况、配置清单文案及修改密码 |
| 服务器维护者         | 在服务器运行 `pnpm reset:passwd` 重置管理密码                                |

管理权限需要在服务器验证，不能仅通过隐藏按钮限制。参与者姓名只作为展示信息，不作为身份凭据。

## 3. 首页与管理入口

### 首页

原始需求：

- 有条目时显示清单，包含标题、开发者、完成情况。
- 没有条目时显示空状态，提示通过右上角设置按钮添加任务列表。
- 无需登录即可浏览和认领。

空状态文案采用“暂无条目，管理员可通过右上角设置添加”。状态显示为“待认领、进行中、已完成”，已完成条目继续保留并排列在列表底部；未完成与已完成两组内分别按录入顺序展示。标记完成后立即移入底部的已完成区域，重新打开或释放认领后回到未完成区域的原录入位置。首页与管理页采用相同排序。

### 可选参与者账号

未登录时仅提供登录或注册入口，不显示“暂不登录”按钮，可直接匿名认领；刷新不阻断。退出参与者账号前需弹窗确认，取消保持登录。注册填写邮箱、密码、确认密码、姓名，登录填写邮箱与密码。邮箱唯一，姓名允许重复；不做邮箱验证或邮件找回。登录后认领直接使用账号姓名。登录时按当前 UUID 自动绑定尚未归属账号的条目，包括已完成条目；保留原姓名及状态，不按 IP 迁移，不覆盖其他账号。详细规则及验收见 [ACC-001](account-system.md)。

### 列表更新

- 页面重新获得焦点时刷新；页面可见时每隔 30 秒刷新列表。
- 自己操作成功后立即更新，不等待下一次定时刷新。
- 服务端以最新数据判断能否认领或完成，页面旧状态不作为操作依据。
- 普通自动刷新或请求失败保留正在填写的姓名。提交认领时若服务端确认条目已被他人认领，在该条目认领人下方的浅红色提示框（红色叉号）显示“该条目已被某某认领”，5 秒后自动消失，清除该条目的姓名草稿并刷新界面，不再展示冲突草稿，不允许覆盖他人的认领。
- 第一版不引入实时通信。具体页面与异常反馈见 [页面与状态说明](pages-and-states.md)。

### 设置与管理页

原始需求：

1. 未设置管理密码时，提示先设置密码。
2. 设置成功后进入管理界面。
3. 已设置密码且没有有效管理会话时，进入管理页面需要输入密码。
4. 管理界面的核心为“新增条目”和“管理现有条目”，另提供清单文案设置、修改密码及退出入口。

已确认：所有管理员及参与者密码最低 8 位，不要求字符组合，初始化、注册、修改和重置统一执行；实现保留现有 128 字符输入上限。

已确认：密码验证成功后，管理会话保持 24 小时，并提供退出入口。修改或重置管理密码后，已有管理会话全部失效，需要重新登录。密码只保存安全哈希，管理会话使用 HttpOnly Cookie。

已确认：部署时提供一次性初始化口令；首次在设置页凭该口令设置管理密码。初始化成功后，口令失效且首次设置入口关闭，管理员直接进入管理界面。初始化口令不得出现在普通页面或浏览器资源中。以后忘记密码通过服务器命令处理，不重新开放初始化入口。

## 4. 批量新增与去重

原始需求：多行输入框加确定按钮；按换行拆分内容，跳过空行。输入内部重复，或者与已有条目标题重复时，整次新增失败并提示用户。

已确认的处理规则：

1. 兼容常见换行格式，去掉每行首尾空白，再跳过空行。
2. 使用处理后的完整标题精确比较；暂不合并大小写、内部空格或不同标点。
3. 任一重复导致整批不写入，提示冲突标题及输入行号，保留输入供用户修改。
4. 已完成条目仍参与去重。仅剩空行时提示“请输入至少一个条目”。
5. 修改标题时执行相同规则，排除当前条目自身。
6. 服务端执行检查和写入，并用事务及唯一约束处理并发新增，避免两个请求同时通过预检查。

示例：已有“实现首页”，输入“实现首页”和“配置部署”时，本次两条均不加入。“实现首页”与“ 实现首页 ”视为重复。

已确认：删除后允许再次添加同名条目，将其视为没有历史认领信息的新条目。

## 5. 认领与管理员维护

匿名参与者填写姓名并确认认领；登录参与者直接使用账号姓名确认认领，任务同时关联账号 ID。两种方式均记录认领时的 IP 和浏览器 UUID。

认领和标记完成均需二次弹窗确认，展示操作条目的标题；认领同时展示将使用的姓名。取消不提交操作，保留姓名输入及原状态。管理员代为完成也需确认。

认领与修改规则：

- 每个条目最多一名认领人，姓名去掉首尾空白后不能为空。
- 两个人同时认领时，仅第一个成功写入的请求获得条目；另一人在对应条目内看到包含当前认领人姓名的临时提示，清除该条目输入并刷新列表。
- 认领后不允许其他访客覆盖认领人，完成后不再开放认领。
- 修改标题保留条目 ID、认领信息和完成情况。
- 删除条目需要确认；界面明确说明删除影响。

已确认的管理员纠错操作：

- 更正认领人的显示姓名，不改变账号归属、认领 IP、UUID 或认领时间；改名不代表转移负责人身份。
- 释放认领：将条目恢复为待认领，清除账号归属、姓名、认领 IP、UUID、认领时间及完成时间。
- 代为完成：将已认领且进行中的条目标记为完成；管理员权限不受参与者 IP 或 UUID 条件限制。
- 重新打开：将已完成条目恢复为进行中，清除完成时间，保留认领信息。
- 换实际负责人时先释放，由新负责人自行认领；不通过修改姓名直接转移。

参与者第一版不能自行取消认领或撤销完成，误操作由管理员处理。待认领条目不能直接完成，管理员同样遵守这一状态规则。

## 6. 浏览器身份与完成权限

原始需求：

- 访问网站时，若浏览器尚无身份标识，则生成 UUID 并保存在浏览器存储中，不主动设置有效期；后续访问复用。
- 认领时记录该 UUID 和服务器获取的访问 IP。
- 未绑定账号的已认领条目：当前 IP 等于认领 IP，或当前 UUID 等于认领 UUID，即可完成。
- 已绑定账号的条目：必须登录对应账号，不允许回退到 IP 或 UUID 放行。管理员纠错仍使用独立管理权限。

建议的校验顺序：服务器确认条目存在且已认领，再验证身份条件，最后更新完成状态与时间。对同一条目的重复完成请求保持幂等。IP 不使用客户端提交的值；反向代理部署时只信任受控代理提供的转发信息。

需要明确的限制：

- IP 不能唯一代表一个人。如果部署网络使服务器看到多个参与者使用相同的来源 IP，他们可能相互完成任务。内网直连时可能取得不同的内网 IP，但内网部署本身并不消除共享来源 IP 的局限。
- UUID 代表浏览器存储中的标识，不代表真实用户。清理存储、无痕模式或换设备后可能变化；“不设有效期”不等于永久存在。
- UUID 应使用不可预测的随机值，不对外展示他人的 UUID 或认领 IP。浏览器存储不可用时应明确提示，避免表现为身份能够长期保留。

已确认：未绑定账号的条目保留“IP 或 UUID 任一匹配”的宽松协作规则，接受共用公网 IP 时其他参与者也可能完成该条目的局限。正式研发项目必须保留相关缺点及后续优化文档，详见 [已知局限与后续优化：AUTH-001](known-limitations.md#auth-001)。此项是已接受的产品取舍，不是当前待修复或阻塞研发的问题。

## 7. 技术与数据存储

已确定技术方向：Next.js、Tailwind CSS、SQLite；管理员密码重置命令为 `pnpm reset:passwd`。该命令现已实现，使用方式及部署配置见 [README](../README.md) 和 [部署说明](deployment.md)。

已确认使用 **SQLite**，支持批量原子写入、标题唯一约束和多人并发认领。部署基线为一台自有服务器、一个应用实例、内网访问及本地持久化数据目录。

建议未来应用使用 `data/` 保存数据库及关联文件，并将整个目录加入 `.gitignore`。数据库放在静态资源目录之外，部署使用持久化磁盘。重新部署和数据库升级不得覆盖已有数据；研发交付须包含数据库升级、备份和恢复说明，并验证恢复方式。临时文件系统或多个各自持有本地数据库的实例不适合直接使用这一方案。

账号增量需要新增参与者账号和会话，并为条目增加可空账号 ID；旧条目迁移后保持未绑定，不能按姓名或 IP 合并归属。参与者密码由管理员针对指定账号重置，使该账号旧会话失效；管理命令 `pnpm reset:passwd` 只负责管理密码。

最小数据概念（原匿名版基础，账号增量见 [ACC-001](account-system.md)）：

| 数据     | 内容                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 站点配置 | 管理密码哈希、会话失效标记、清单名称、简短说明及列名                          |
| 条目     | 稳定 ID、标题、认领人、认领 UUID、认领 IP、认领时间、完成时间、创建及更新时间 |

建议从认领信息和完成时间推导三个状态，避免独立状态字段与实际数据相互矛盾。尚未认领的条目不允许直接完成。公开接口仅返回展示所需字段。

密码重置规则：命令通过隐藏输入设置新密码并使旧管理会话失效；保留清单和认领数据，不回到允许任意访客初始化密码的状态。重置失败时保留旧凭据。数据库备份需覆盖认领信息与配置；Git 不承担运行数据备份。

## 8. 怎样适用于类似场景

已确认：第一版只做一个清单，通过名称和字段文案适配不同用途。复用同一套认领及完成规则，以下为展示示例：

| 场景     | 条目标题示例 | 认领人文案 | 结束状态文案 |
| -------- | ------------ | ---------- | ------------ |
| 软件开发 | 实现搜索功能 | 开发者     | 已完成       |
| 活动准备 | 布置签到台   | 负责人     | 已完成       |
| 志愿分工 | 整理捐赠物资 | 志愿者     | 已完成       |

第一版不支持同时管理多个独立清单。已确认在管理页提供清单名称、简短说明，以及“条目／认领人／状态”三个列名的配置。状态值固定为“待认领／进行中／已完成”，不开放自定义状态。修改文案只改变显示，不改变数据类型或权限规则。

建议默认清单名称为“认领清单”，说明为空，列名为“条目、认领人、状态”。部署者可以将其改为“开发任务”和“任务、开发者、完成情况”。多人共同认领、数量配额、截止时间、周期任务和自定义字段属于进一步扩展，不因通用性要求而默认加入。

## 10. 验收场景

- 空清单展示添加指引；有条目时展示标题、认领人及状态。
- 站点仅在预定内网范围可访问；内部参与者无需登录即可查看和认领。
- 未初始化、密码错误、密码正确分别进入对应流程；未验证请求不能修改管理数据。
- 首次设置必须提供有效初始化口令；初始化后口令和首次设置入口失效。
- 管理会话在 24 小时后失效；主动退出、修改或重置密码按规则使对应会话失效。
- 多行输入跳过空行；批内或已有标题冲突时整批失败，且保留输入。
- 同时提交相同标题不会产生重复项；同时认领一个条目只有一人成功。
- 修改标题执行相同去重规则；删除后重建同名条目不继承旧认领信息。
- 管理员修改姓名不转移认领身份；释放认领清空归属信息；重新打开保留原认领人。
- 管理员可代为完成已认领条目；参与者不能自行取消认领或撤销完成。
- 页面可见时每 30 秒刷新，重新获得焦点及自身操作成功后更新；刷新或失败不清空正在填写的姓名。
- 清单名称、说明及三个列名可配置；状态值保持固定，改文案不改变操作规则。
- 未绑定账号的条目保留同 UUID 不同 IP、同 IP 不同 UUID 均可完成；两者均不匹配时拒绝。已绑定账号的条目仅允许对应账号完成，退出后不能依赖 IP 或 UUID 操作。
- 账号注册、自动绑定、跨设备操作、密码恢复和迁移验收按 [ACC-001 第 7 节](account-system.md#7-新增验收清单已完成) 执行。
- 重复完成请求不改变首次完成时间；未认领条目不能被完成。
- 普通访客看不到认领 IP、UUID、密码哈希或管理会话信息。
- 应用重启、重新部署及数据库升级后数据仍存在；备份可恢复；重置密码后旧密码及旧会话失效，已有条目保留。
- 正式研发仓库包含 AUTH-001 的规则、已知局限、接受原因和后续优化方向，并从其 README 或文档索引提供入口。

原匿名版功能已有对应测试与验证记录；新增账号功能已通过专项验收。历史证据详见 [验收记录](verification.md)。具体服务器的内网访问范围和运行环境由部署者现场验收。
