# ClaimList：页面与状态说明

账号增量已实现并通过专项验收，详见 [ACC-001](account-system.md) 和 [验收记录](verification.md)。

依据：[第一版产品需求](product-requirements.md)。本文将已确认的规则串成页面流程；页面路径、布局和具体提示措辞是研发参考，可在不改变业务规则的前提下调整。

## 1. 页面组成

| 页面     | 内容与入口                                               |
| -------- | -------------------------------------------------------- |
| 首页     | 清单名称、简短说明、条目列表；右上角设置入口             |
| 首次设置 | 一次性初始化口令、新管理密码、确认密码、设置按钮         |
| 管理登录 | 管理密码输入、登录按钮；提示忘记密码时联系服务器维护者   |
| 管理页   | 批量新增、现有条目维护、清单文案设置、修改密码及退出入口 |

设置入口按服务器状态分流：尚未初始化则显示首次设置；已经初始化但没有有效管理会话则显示登录；已有有效会话则进入管理页。首页始终允许内网参与者无需登录浏览和认领。

### 新增参与者登录与注册

首页账号模块位于顶部导航分隔线下方、清单标题上方；桌面和手机使用相同顺序，空清单时仍保留。模块仅提供登录与注册入口，不显示“暂不登录”按钮；未登录可直接匿名使用，以浅黄色背景、黄色边框和警告图标提示“正在匿名使用。登录后可跨设备管理已认领的任务。”，其中匿名状态加粗注册表单包含邮箱、密码、确认密码和姓名；登录表单仅包含邮箱和密码。登录成功后自动关联当前 UUID 下尚未绑定账号的任务，显示实际关联数量；关联失败不提示成功。登录后展示账号姓名及退出入口；点击退出先弹窗确认，取消保持登录，确认后退出当前会话。认领无需重复填写姓名。参与者登录与管理员登录明确区分。

## 2. 首页与参与者操作

列表先展示未完成条目，再展示已完成条目，两组内各按录入顺序排列。标记完成成功后立即沉入底部的已完成区域；管理员重新打开或释放认领后，条目回到未完成区域的原录入位置。管理页现有条目使用同一排序。

| 状态                   | 页面显示                                           | 可执行的操作                         |
| ---------------------- | -------------------------------------------------- | ------------------------------------ |
| 加载中                 | 加载提示                                           | 等待或失败后重试，不提前显示空清单   |
| 无条目                 | “暂无条目，管理员可通过右上角设置添加”             | 打开设置                             |
| 待认领                 | 标题、匿名时姓名输入框／登录时仅认领按钮、“待认领” | 匿名填写姓名／登录后直接确认认领     |
| 进行中且符合完成条件   | 标题、认领人、“进行中”                             | 标记完成                             |
| 进行中但不符合完成条件 | 标题、认领人、“进行中”                             | 仅查看，不显示完成按钮或常驻权限提示 |
| 已完成                 | 标题、认领人、“已完成”                             | 查看                                 |

认领步骤：匿名填写姓名／登录后使用账号姓名 → 点击认领 → 弹窗显示认领姓名与条目标题，二次确认后提交 → 服务器检查状态并记录姓名、IP、UUID 及适用的账号 ID → 成功后显示进行中。匿名姓名为空时在输入位置提示，不提交无效认领；取消确认不发送操作请求，保留姓名草稿。

登录后，待认领条目的认领人区域仅显示“认领”按钮，不预先展示自己的姓名；姓名在确认弹窗中核对，认领成功后才作为该条目的认领人展示。

完成步骤：点击标记完成 → 弹窗显示条目标题，二次确认后提交；取消则保持原状态 → 服务器检查条目归属：未绑定账号时匹配 IP 或 UUID，已绑定时验证对应账号会话 → 成功后显示已完成。前端按钮状态只是操作引导，不能代替服务端检查，也不能通过返回他人的 IP 或 UUID 来判断权限。

认领或标记完成成功后，在对应条目认领人下方显示浅绿色提示框及绿色勾号，5 秒后自动消失。认领冲突使用同一位置的浅红色提示框及红色叉号。

提交中暂时禁用对应按钮，避免重复操作。普通参与者不显示释放认领、修改认领人或撤销完成入口。

## 3. 管理员初始化与登录

- 首次设置同时校验一次性初始化口令与两次密码输入；失败保留非敏感页面状态并提示原因，不创建管理权限。
- 初始化成功后进入管理页，关闭初始化入口；已经初始化的站点不能再次使用旧口令创建或覆盖密码。
- 正确密码建立 24 小时管理会话；错误密码留在登录页并给出提示。
- 会话过期时要求重新登录；尚未提交的普通文本草稿尽量保留，但不持久保存管理密码或初始化口令。
- 管理员可主动退出。修改密码后全部旧会话失效，当前页面也返回登录流程。
- 登录页可提示维护者在服务器运行 `pnpm reset:passwd`，不提供无需验证的网页重置入口。

## 4. 管理页

### 批量新增

显示多行输入框与确定按钮，说明“一行一个条目，空行跳过，重复时整批不添加”。

成功后更新当前条目列表并提示新增数量；此时可清空已成功提交的输入。发现重复时列出冲突标题和输入行号，保留全文供修改。标题处理与去重规则以需求文档为准。

### 现有条目维护

每个条目显示标题、认领人和状态，按状态提供操作：

| 操作     | 适用状态       | 结果                                               |
| -------- | -------------- | -------------------------------------------------- |
| 修改标题 | 所有状态       | 保持条目 ID、认领与完成信息，执行标题去重          |
| 更正姓名 | 进行中、已完成 | 仅修改展示姓名，保留账号归属、认领 IP、UUID 和时间 |
| 释放认领 | 进行中、已完成 | 回到待认领，清空账号归属、认领信息及完成时间       |
| 代为完成 | 进行中         | 保留认领信息，记录完成时间                         |
| 重新打开 | 已完成         | 回到进行中，保留认领信息，清空完成时间             |
| 删除     | 所有状态       | 删除条目；重新添加同名条目视为新条目               |

删除、释放认领及代为完成必须弹窗确认。释放认领提示明确将清除归属和完成信息；代为完成显示条目标题，取消不提交。界面说明“更正姓名不会转移实际负责人；换人请先释放，再由新负责人认领”。

### 参与者密码恢复

管理页允许管理员为指定参与者账号重置密码，失效该账号已有会话并保留任务归属。普通参与者登录不获得此权限。`pnpm reset:passwd` 继续只处理管理密码。

### 清单文案与管理密码

文案设置提供清单名称、简短说明、标题列名、认领人列名和状态列名。保存后首页使用新文案；“待认领、进行中、已完成”三个状态值保持固定。

修改管理密码与文案保存使用独立操作，避免一次保存意外改变凭据。所有密码最低 8 位，不要求字符组合，保留 128 字符输入上限；管理员初始化、网页修改、服务器重置以及参与者注册和重置保持一致。

## 5. 刷新与异常反馈

列表在页面重新获得焦点时更新，页面可见时每 30 秒更新，自身操作成功后立即更新。普通刷新只更新服务器数据，不重置用户当前输入或编辑草稿；服务端确认认领冲突时按下表清除该条目的姓名草稿。

| 场景               | 反馈与处理                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 标题重复           | 整批失败，指出冲突和行号，保留输入                                                                                               |
| 认领时已被别人认领 | 在该条目认领人下方显示浅红色提示框及红色叉号“该条目已被某某认领”（5 秒后消失，不含草稿输入或按钮），清除该条目姓名草稿并刷新列表 |
| 完成权限不匹配     | 提示“当前身份不符合该条目的完成条件，请联系管理员”，状态不变                                                                     |
| 条目已删除         | 提示“该条目已不存在”，更新列表；保留未提交草稿供复制                                                                             |
| 管理会话过期       | 提示重新登录，不执行未经验证的管理操作                                                                                           |
| 列表刷新失败       | 保留最近一次成功内容并提示更新失败，不将旧数据表现为已更新                                                                       |
| 提交后网络中断     | 提示“暂时无法确认结果”，保留输入并重新读取状态，不直接认定操作未成功                                                             |
| 浏览器存储不可用   | 提示无法持久保留浏览器身份及身份丢失的影响，不承诺下次访问仍能识别                                                               |

重复完成请求不改变首次完成时间。自动刷新发现正在编辑的条目已变化时，提示用户核对最新内容，不能静默丢弃草稿或覆盖其他人的认领结果。

新增账号异常反馈：重复邮箱、两次密码不一致、空姓名分别提示；普通账号登录失败不进入登录态；账号任务未登录时提示登录，登录了其他账号时提示归属不匹配。关联任务失败保留既有归属，不显示成功数量。退出或会话失效后刷新按钮权限；提交认领时若登录态已失效，要求重新登录或明确选择匿名使用，不能静默以匿名身份认领。

## 6. 研发交接

正式研发需覆盖空清单、正常流程和上述异常状态，带入 [AUTH-001 已知局限](known-limitations.md#auth-001)，并落实数据库升级、备份恢复和内网部署说明。原匿名版业务页面和操作已有实现及验证记录；新增账号交互已通过专项验收，详见 [验收记录](verification.md)。不同服务器的部署地址和访问范围仍由部署者配置。
